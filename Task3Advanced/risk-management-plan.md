# План управления рисками

## Технические меры

### R1. Целостность данных
- **Стратегия:** Strangler Fig + Reverse ETL + сверка контрольных сумм
- **Инструменты:** Debezium для CDC, DBT для трансформаций, Great Expectations для валидации
- **Процесс:** Параллельная работа старого DWH и нового Data Lake 6 месяцев с ежедневной сверкой
- **KPI:** Расхождение данных < 0.01%

### R2. Утечка медицинских данных
- **Стратегия:** Privacy by Design + Defence in Depth
- **Инструменты:**
    - Токенизация PII на уровне ingestion (Hashicorp Vault)
    - Apache Ranger для разграничения доступа на уровне колонок
    - Audit logging всех запросов к медицинским данным
- **Процесс:** Автоматическая проверка всех ETL-пайплайнов на наличие незамаскированных полей перед деплоем
- **KPI:** Ноль инцидентов за год

### R4. Производительность
- **Стратегия:** Auto-scaling + Load testing
- **Инструменты:**
    - Kubernetes HPA для доменных сервисов
    - ClickHouse шардирование и репликация
    - Kafka partitioning по ключу домена
- **Процесс:** Ежемесячное нагрузочное тестирование с профилированием
- **KPI:** P95 latency < 2 сек для аналитических запросов

### R5. Регуляторные требования
- **Стратегия:** Compliance as Code
- **Инструменты:** Yandex Cloud Федеральный регион (аттестованный), шифрование KMS
- **Процесс:** Аудит архитектуры регуляторами до начала миграции
- **KPI:** Сертификация инфраструктуры к концу 1-го этапа

### R10. Отказ Kafka
- **Стратегия:** High Availability + Disaster Recovery
- **Инструменты:**
    - Kafka кластер из 3 брокеров в разных зонах доступности
    - MirrorMaker 2 для георепликации
    - Dead Letter Queue для обработки ошибок
- **Процесс:** Регулярное тестирование failover-сценариев
- **KPI:** RTO < 15 минут, RPO < 1 минута

## Организационные меры

### R3. Сопротивление пользователей
- **Стратегия:** Change Management + Ранние последователи
- **Меры:**
    - Пилотная группа из 10% пользователей на этапе 1
    - Power BI остаётся как фронтенд (меняется только источник данных)
    - Еженедельные демо и сбор обратной связи
    - Геймификация обучения (баллы за прохождение курсов)
- **KPI:** Удовлетворённость > 4.0 из 5 через 3 месяца

### R8. Нехватка компетенций
- **Стратегия:** Build + Buy + Borrow
- **Меры:**
    - Внутреннее обучение: курсы по Kafka, ClickHouse, DDD
    - Внешний найм: 3 senior инженера на ключевые роли
    - Партнёрство: привлечение Yandex Cloud архитекторов на этапе проектирования
    - Центр компетенций: выделенная команда Data Platform (5 человек)
- **KPI:** 80% команды сертифицированы к концу 1-го года

### R9. Срыв сроков
- **Стратегия:** Agile + MVP + Инкрементальная поставка
- **Меры:**
    - Разбиение на 6-недельные инкременты с измеримыми результатами
    - Приоритизация доменов по бизнес-ценности (Fintech первый)
    - Выделенный миграционный бэклог с оценкой сложности
    - Ежемесячный steering committee с бизнес-спонсорами
- **KPI:** Отклонение от плана < 20%

### R11. Конфликты владения данными
- **Стратегия:** Data Mesh governance
- **Меры:**
    - Назначение Data Owners в каждом домене
    - Data Product Contract: схема, SLA, качество данных
    - Единый Data Catalog (DataHub) с указанием владельцев
    - Регулярные встречи Data Council (раз в 2 недели)
- **KPI:** Разрешение конфликтов < 1 неделя
