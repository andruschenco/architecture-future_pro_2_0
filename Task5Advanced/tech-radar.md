# Расширенный технический радар «Будущее 2.0»

## Структура радара

Радар использует классификацию, расширенную под специфику компании:

### Квадранты (4)

| Квадрант                       | Описание                                  | Примеры                                     |
|--------------------------------|-------------------------------------------|---------------------------------------------|
| **Архитектурные паттерны**     | Методологии и подходы к построению систем | Data Mesh, Event-Driven Architecture, CQRS  |
| **Языки и фреймворки**         | Средства разработки сервисов              | Go, Java, Python, Spring Boot               |
| **Платформы и инфраструктура** | Облачные сервисы, базы данных, хранилища  | Managed Kafka, ClickHouse, PostgreSQL, S3   |
| **Методы и практики**          | Организационные и инженерные практики     | Domain-Driven Design, CI/CD, Data Contracts |

### Кольца (4)

| Кольцо     | Описание                                           | Когда применять                          |
|------------|----------------------------------------------------|------------------------------------------|
| **Adopt**  | Активно используем, рекомендуем для новых проектов | Проверено в проде, low risk              |
| **Trial**  | Пробуем в пилоте, оцениваем ограничения            | Успешно в 1–2 проектах, нужна проверка   |
| **Assess** | Изучаем, готовим proof-of-concept                  | Перспективно, но нет практического опыта |
| **Hold**   | Выводим из эксплуатации, не применяем в новом      | Легаси, высокие риски, дорого            |

## Расширенный технический радар

### Архитектурные паттерны

| Технология / Паттерн                                | Статус  | Движение  | Обоснование                                               |
|-----------------------------------------------------|---------|-----------|-----------------------------------------------------------|
| **Data Mesh**                                       | Adopt   | ↑ Новое   | Целевая архитектура, обеспечивает независимость доменов   |
| **Event-Driven Architecture**                       | Adopt   | ↑ Новое   | Основа интеграции через Kafka, заменяет синхронные вызовы |
| **CQRS (Command Query Responsibility Segregation)** | Trial   | →         | Разделение чтения и записи для высоконагруженных сервисов |
| **Self-Service BI**                                 | Adopt   | ↑ Новое   | Замена монолитной BI, ускорение аналитики                 |
| **Domain-Driven Design (DDD)**                      | Adopt   | ↑ Новое   | Основа для выделения bounded contexts                     |
| **Strangler Fig Pattern**                           | Adopt   | →         | Стратегия миграции с легаси                               |
| **Microservices**                                   | Trial   | →         | Для критичных доменов, не для всего                       |
| **Monolithic DWH**                                  | Hold    | ↓         | Заменяется на Data Lake + доменные витрины                |
| **ESB Integration**                                 | Hold    | ↓         | Заменяется на Event Bus (Kafka)                           |
| **Batch ETL**                                       | Hold    | ↓         | Заменяется на Streaming ETL                               |
