## Модуль `vm`

Модуль создаёт виртуальную машину в Yandex Cloud с подключаемым диском и сетевым интерфейсом.

### Параметры модуля

| Параметр         | Тип         | Обязательный | По умолчанию      | Описание                                    |
|------------------|-------------|--------------|-------------------|---------------------------------------------|
| `vm_name`        | string      | Да           | —                 | Имя виртуальной машины                      |
| `cpu_cores`      | number      | Да           | —                 | Количество ядер CPU (1–64)                  |
| `ram_mb`         | number      | Да           | —                 | Объём RAM в мегабайтах (512–524288)         |
| `disk_size_gb`   | number      | Да           | —                 | Размер загрузочного диска в ГБ (10–4096)    |
| `subnet_id`      | string      | Да           | —                 | Идентификатор подсети                       |
| `ssh_public_key` | string      | Да           | —                 | Публичный SSH-ключ                          |
| `disk_type`      | string      | Нет          | `network-ssd`     | Тип диска (`network-ssd` или `network-hdd`) |
| `image_id`       | string      | Нет          | `ubuntu-2204-lts` | Идентификатор образа ОС                     |
| `zone`           | string      | Нет          | `ru-central1-a`   | Зона доступности                            |
| `environment`    | string      | Нет          | `dev`             | Название окружения                          |
| `labels`         | map(string) | Нет          | `{}`              | Дополнительные метки ресурсов               |

### Выходные переменные модуля

| Выход            | Тип    | Описание                         |
|------------------|--------|----------------------------------|
| `vm_id`          | string | Идентификатор созданной ВМ       |
| `vm_name`        | string | Имя ВМ                           |
| `vm_internal_ip` | string | Внутренний IP-адрес              |
| `vm_external_ip` | string | Внешний IP-адрес                 |
| `vm_fqdn`        | string | Полное доменное имя ВМ           |
| `disk_id`        | string | Идентификатор загрузочного диска |
| `subnet_id`      | string | Идентификатор подсети            |
| `cpu_cores`      | number | Количество ядер CPU              |
| `ram_mb`         | number | Объём оперативной памяти         |



### Особенности реализации

- **Без хардкода окружений** — все значения передаются через переменные
- **Валидация входных данных** — проверка допустимых значений ядер, памяти, размера диска
- **Метки по умолчанию** — `managed_by: terraform` и `environment` на всех ресурсах
- **Чувствительные данные** — SSH-ключ помечен как `sensitive`

## Окружения

Каждое окружение находится в отдельной директории `envs/` и содержит собственный файл `terraform.tfvars` с конфигурацией виртуальных машин.

| Окружение | Количество ВМ | Зона            | Типичные ресурсы                          |
|-----------|---------------|-----------------|-------------------------------------------|
| **dev**   | 2             | `ru-central1-a` | 2–4 ядра, 2–8 ГБ RAM, 30–60 ГБ диск       |
| **stage** | 4             | `ru-central1-b` | 4–8 ядер, 8–32 ГБ RAM, 50–200 ГБ диск     |
| **prod**  | 6             | `ru-central1-c` | 8–32 ядра, 16–128 ГБ RAM, 100–500 ГБ диск |

## Запуск

### Предварительные требования

1. **Аккаунт Yandex Cloud** с активным каталогом
2. **Сервисный аккаунт** с ролью `compute.admin`
3. **Статические ключи доступа** для хранения состояния
4. **Terraform** >= 1.3.0

### Развёртывание окружения

```powershell
# Перейти в директорию окружения
cd envs/dev

# Инициализация
terraform init `
  -backend-config="bucket=future2-terraform-state-dev" `
  -backend-config="key=dev/terraform.tfstate"

# Просмотр плана
terraform plan -var-file="terraform.tfvars"

# Применение
terraform apply -var-file="terraform.tfvars"
```

### Различия между окружениями

Вся разница между окружениями задаётся только в файле `terraform.tfvars`. Код модуля и конфигурация `main.tf` идентичны для всех сред.

## Переиспользуемость модуля

Модуль `vm` спроектирован для использования в любых окружениях:

- **Один вызов — одна ВМ** — через `for_each` создаётся нужное количество машин
- **Гибкие параметры** — каждая ВМ может иметь уникальные характеристики
- **Независимость от окружения** — нет привязки к именам или конфигурациям конкретных сред
- **Совместимость** — модуль можно использовать отдельно от проекта в других конфигурациях

## Хранение состояния

Состояние Terraform хранится в Yandex Object Storage (S3-совместимое хранилище):

| Окружение | Бакет                           | Ключ                      |
|-----------|---------------------------------|---------------------------|
| dev       | `future2-terraform-state-dev`   | `dev/terraform.tfstate`   |
| stage     | `future2-terraform-state-stage` | `stage/terraform.tfstate` |
| prod      | `future2-terraform-state-prod`  | `prod/terraform.tfstate`  |
